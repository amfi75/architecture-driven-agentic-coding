# Contributing

Start with the [agent reading guide](SETUP.md) and [method overview](method/README.md). The [core](releases/2.4.0-dev.2/core.md) defines the shared commitments. Use repository issues for reproducible problems or questions and pull requests for proposed changes.

Describe the problem, intended outcome, affected commitments and evidence. Small fixes need proportionate checks. Substantial changes follow the core's plan/review/approval and final-review process. Recommendations cannot silently change a core obligation.

Keep the method usable as text. Do not add required installers, model routers, private services or mandatory agent-specific configuration. Avoid unsupported performance claims. Use synthetic data and never submit credentials or private operational details.

Released versioned text is immutable. Propose changed release text under a new version and explain migration; do not overwrite an existing snapshot. See [maintainer checks](docs/maintaining.md); they are optional tooling for contributors, not requirements for ADAC users.

Use clear, respectful, evidence-based discussion. New original contributions are submitted under the repository's MIT license; identify third-party material and its license explicitly.

Keep private project implementations, their fixtures and their verification records outside the public distribution. Check both exported files and the complete publication history before release.
