# ADAC 2.4.0-dev.2

Development candidate, not a stable release. At one fixed source revision, read [core 2.4.0-dev.2](core.md) for the complete method; consult [capability recommendations 1.3.0](recommendations.md) when useful. These three files form a portable standalone snapshot. Copying is optional; no runtime, installer, skill or provider is required.

ADAC pursues maintainable modular software of high quality, faster implementation through controlled parallel work, and autonomous completion. Use it when meaningful responsibilities and interfaces support coordinated delivery; keep local or inseparable tasks proportionate.

## Start

> Read this snapshot's core.md and apply it to: [task]. Understand the requirements and existing system first. Assess suitability, derive meaningful architecture and interfaces, investigate consequential uncertainty, and prepare the required reviewed plan. Give component owners purpose, derived requirements, design discretion and evidence expectations. Preserve binding requirements through autonomous delivery and validate the integrated result. Consult recommendations.md when useful.

The core supplies approval, authority and completion rules. In the full repository, SETUP.md also routes readers to relevant explanatory guides at the same commit. They add no hidden commitments to this standalone snapshot.

## What changed

Dev.2 clarifies functional understanding as an architectural input, delegated design/research ownership, bounded investigation and intended-use validation. Structured natural language and conditional guide reading reduce repeated context. It retains dev.1's system-understanding, safe-change and authority rules. Previous snapshots remain unchanged; existing projects migrate only deliberately.

The candidate has text/static verification, not new adoption trials or empirical performance claims. Agents must follow the instructions using capabilities actually available.
