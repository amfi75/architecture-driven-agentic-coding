# Change request

A compact message is enough; this optional record helps complex changes.

- Requesting worker and orchestrator:
- Related overall and derived requirements:
- Current interface/assignment revision and exact unmet need:
- Why the current contract or scope is insufficient:
- Affected components, consumers and tasks:
- Proposed change and alternatives:
- Compatibility, quality and integration consequences:
- Suggested verification:
- Dependent work paused; independent work continuing:

## Orchestrator decision

- Decision and reason:
- Authority basis: derived internal decision, or an actual overall-requirement/binding-constraint delta:
- If a requirement delta is needed: precise proposal, user approval record and affected plan review; do not proceed on an unanswered request:
- Updated common interface/task revision and recipients:
- Implementation and integration ownership/sequencing:
- Actual verification and closure:

Changing a derived assignment is not itself changing the user's overall requirements. See [change workflow](../method/change-request-workflow.md).
